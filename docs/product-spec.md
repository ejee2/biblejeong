# 성경 곁에서 · 제품 기획서 v1.3

작성일: 2026-10-17
기준: 기존 읽기·마이페이지·구절 표시·개인 묵상을 유지하고, 장 페이지 구분을 책 단위 이어 읽기로 바꾼다. 사용자는 개역개정 전문 이용허락 미확보 상태이며 확보 방법 안내를 요청했다.
협업: 화면 개발 / 저장 연결 / GitHub 배포 역할과 기획·디자인 역할의 통합 검토.

> 성경을 이어 읽다가 궁금한 구절의 배경을 확인하고, 뜻깊은 구절을 표시해 개인 묵상과 함께 다시 살펴보는 페이지.

## 1. 목적과 범위

성경 통독을 숙제로 만들지 않고 이해를 돕는다. 모바일·태블릿·PC 반응형 웹으로 제공하며 개역개정 기준, 본문 근거가 있는 사실 설명, 필요한 경우에만 권리 확인된 이미지라는 원칙을 유지한다. 로그인·서버 DB 없이 개인이 GitHub Pages에서 사용한다.

주 화면은 읽기와 마이페이지 두 개다. 별도 홈·홍보·통계·프로필 페이지는 없다. 통독 일정·과제·분량·완료·진도율·연속 읽기·알림·그룹·초대·관리자 기능은 만들지 않는다. 태그·자유 메모장·클라우드 동기화도 제외한다. 기존 ‘메모 제외’ 원칙에서 이번에 요청한 구절별 개인 묵상만 예외로 포함한다.

## 2. 추가 요구 검토와 통합 결정

| 검토 | 결정 |
| --- | --- |
| 기획 | 저장한 각 절에 개인 묵상 하나를 연결한다. 작성하지 않아도 읽기·저장을 사용할 수 있다. |
| 디자인 | 마이페이지의 구절 아래에 ‘나의 묵상’을 놓는다. 차분한 기존 색·글꼴을 재사용하고 큰 카드나 추가 대시보드를 만들지 않는다. |
| 화면 개발 | 읽기와 마이페이지는 별도 주소로 나눈다. 묵상은 일반 텍스트 영역과 명시적 저장·취소를 사용한다. |
| 저장 연결 | 저장 성공을 확인한 뒤 화면을 갱신한다. 실패 시 이전 저장값과 작성 초안을 유지한다. |
| 게시 | 공개 저장소와 배포 파일에는 개인 묵상을 넣지 않는다. 데이터는 이용하는 브라우저에만 저장한다. |

사용자 묵상은 개인의 생각이다. 서비스가 작성한 성경 사실 설명이나 개역개정 원문과 섞지 않는다. 묵상을 AI로 평가하거나 교훈을 자동 생성하지 않는다.

## 3. 페이지와 탐색

| 페이지 | 주소 | 구성 |
| --- | --- | --- |
| 읽기 | /biblejeong/ | 책 선택, 책 단위 연속 본문, 선택적 장 바로가기, 구절 선택, 도움, 근거, 구절 표시, 읽기 설정 |
| 마이페이지 | /biblejeong/mypage/ | 저장 구절, 최근 표시순·성경순, 저장된 책 필터, 개인 묵상, 본문 복귀, 표시 해제 |

각 주소로 직접 열기와 새로고침이 가능해야 한다. 마이페이지의 ‘본문에서 보기’는 같은 번역·책·장·절 정보를 읽기 페이지에 전달한다. 예를 들어 book=1th, chapter=5, verse=18을 사용하며 URL 값은 검증한다. 잘못된 주소를 임의의 구절로 바꾸지 않는다.

상단에서 두 페이지를 오간다. PC는 원문과 오른쪽 도움을 함께 보여 주고, 좁은 화면은 선택 구절의 도움으로 전환한다. 도움만 닫으면 본문 위치와 초점을 복원한다. 마이페이지는 계정 정보 페이지가 아닌 개인 저장 목록이다.

## 4. 연속 본문과 사실 설명

읽기 경험은 책 선택 → 책 안의 모든 등록된 장을 연속 스크롤 → 구절 클릭 → 해당 구절의 배경과 근거 → 읽기 계속이다. 책 제목은 상단에, 장 번호는 본문 안의 소제목으로 표시한다. ‘장 바로가기’는 같은 책 안의 위치 이동이며 장마다 별도 읽기 화면을 만들지 않는다. 하단은 이전·다음 책 이동이다.

구절을 눌러 설명을 여는 행동만으로 저장하지 않는다. 현재 선택은 세로선·절 번호로, 저장 구절은 밑줄과 옅은 세이지 배경을 함께 적용해 구별한다. 서로 다른 장의 같은 절 번호가 충돌하지 않도록 책·장·절로 선택과 DOM 주소를 식별한다. 마이페이지나 직접 장절 링크는 책 전체를 연 뒤 해당 위치로 이동한다. 모바일 도움을 닫을 때도 선택한 장절과 스크롤 위치를 유지한다.

개역개정 66권 전문은 이용허락 및 허용된 자료 확보 후 연결한다. 현재 발췌 범위를 표시하며, 미수록 책에 빈 장 50개 같은 가짜 연속 본문을 나열하지 않는다. 공식 본문 링크를 제공하고, 다른 번역으로 임의 교체하지 않는다.

PC 1440px 기준 외곽 여백은 좌우 48px, 본문 실제 최대 폭은 840px, 오른쪽 도움은 368px를 기준으로 한다. 320px와 글자 200% 확대에서도 본문과 묵상에 가로 넘침이 없어야 한다. 무드 톤과 충분한 텍스트 명암을 유지하며 밝은·어두운 테마의 배경과 글자를 함께 적용한다.

설명은 본문에 명시된 행동·관계·권면·화자·대상만 정리한다. 각 사실에 근거 장절을 연결하며 근거를 여는 것만으로 읽는 장을 바꾸지 않는다. 집필 연대·장소·심리·동기·외부 역사·문화 견해를 근거 없이 채우지 않는다. 서술 순서와 실제 시간 순서를 구별한다. 미등록 설명과 본문 미명시 정보도 구별한다.

도움의 항목은 현재 내용, 앞선 흐름, 인물·장소 또는 화자·대상, 필요한 이미지, 이후 연결이다. 이후 연결은 기본 접힘이다. 등록된 설명이 선택 구절을 포함할 때만 연결하고 설명 범위를 밝힌다. 무관한 설명을 자동 대체하지 않는다.

## 5. 구절 표시와 마이페이지

표시 단위는 번역·책·장·절로 식별되는 절 전체다. 부분 단어 선택·여러 절 일괄 표시·색상별 분류는 없다. 같은 구절은 중복 저장하지 않는다. 반복 선택으로 표시 시각을 바꾸지 않으며 해제 후 새로 표시할 때만 새 시각을 쓴다.

마이페이지의 각 행에는 장절·번역, 제공 가능한 본문, ‘나의 묵상’, ‘본문에서 보기’, ‘표시 해제’를 둔다. 원문은 공통 콘텐츠 자료에서 참조하고 사용자 저장 데이터에 복제하지 않는다. 기본은 최근 표시순이며 성경순은 책→장→절 순서다. 책 필터에는 전체 성경과 저장된 구절이 있는 책만 제공한다.

마지막 구절이 사라지면 빈 상태를 보여 준다. 필터 대상 책의 마지막 항목이 사라지면 전체 성경으로 돌아간다. 필터·정렬·묵상 수정으로 표시 시각을 바꾸거나 읽기 진도를 계산하지 않는다.

## 6. 구절별 개인 묵상

표시한 구절마다 개인 묵상 한 개를 연결한다. 작성 위치는 마이페이지의 구절 바로 아래이고 레이블은 ‘나의 묵상’이다.

| 상태 | 화면과 동작 |
| --- | --- |
| 미작성 | ‘이 구절을 읽으며 남기고 싶은 생각을 적어보세요.’ / ‘묵상 쓰기’ |
| 작성·수정 | 장절과 연결된 레이블, 일반 텍스트 영역, 현재 글자 수 / 10,000자, ‘묵상 저장’, ‘취소’ |
| 저장 후 | 줄바꿈을 유지한 묵상 본문 / ‘묵상 수정’ |
| 저장 실패 | ‘묵상을 저장하지 못했습니다. 작성한 내용은 그대로 남아 있습니다.’ / 초안 유지, 다시 저장 |
| 빈 내용 저장 | 공백·줄바꿈만 있으면 묵상만 비움. 구절 표시와 표시 시각은 유지 |
| 글자 수 초과 | ‘묵상은 10,000자까지 입력할 수 있습니다.’ / 저장 차단, 초안 유지 |

최대 10,000자의 일반 텍스트만 받는다. HTML·Markdown을 실행하거나 자동 해석·자동 링크로 변환하지 않는다. 묵상 본문은 텍스트로 렌더링하고 줄바꿈을 유지한다. 긴 글도 목록에서 자연스럽게 늘어난다. 모바일 입력 영역은 최소 6줄 높이로 시작하고 저장·취소 조작 영역을 충분히 확보한다.

저장 성공 전에는 기존 묵상을 바꾸지 않는다. 취소는 편집 전 저장 내용으로 돌아간다. 실제로 바뀐 미저장 초안이 있을 때 다른 구절 편집·페이지 이동·정렬·필터처럼 초안을 숨기는 행동을 하면 확인한다. 변경 없는 폼에는 불필요한 확인을 하지 않는다.

확인 문구는 ‘저장하지 않은 묵상이 있습니다. 이동하면 작성한 내용이 사라집니다.’다. ‘계속 작성’은 초안과 초점을 유지하고, ‘저장하지 않고 이동’만 초안을 버린 뒤 요청한 행동을 수행한다. 새로고침·탭 종료에는 브라우저의 표준 이탈 확인을 사용하며 문구가 항상 같다고 약속하지 않는다.

## 7. 표시 해제·묵상 삭제·되돌리기

묵상이 없는 구절은 즉시 표시를 해제할 수 있다. 저장된 묵상이 있는 구절은 ‘표시를 해제하면 이 구절의 묵상도 함께 삭제됩니다.’와 취소·표시 해제를 확인한 뒤 실행한다. 취소하면 구절과 묵상을 그대로 둔다.

미저장 변경이 있는 구절의 해제도 초안을 잃는 동작이므로 먼저 보존·폐기 선택을 거친다. 저장 또는 해제가 실패하면 초안·기존 묵상·구절 표시를 유지한다.

해제 후 ‘구절 표시를 해제했습니다. 되돌리기’를 제공한다. 직전 해제 한 건만 복원하며 다른 표시 변경이나 페이지 이동 전까지 버튼을 유지한다. 시간 제한으로 먼저 사라지지 않는다. 되돌리면 구절·묵상·표시 시각·묵상 수정 시각·정렬 위치를 함께 복원하고 중복을 만들지 않는다.

## 8. 저장과 개인정보

저장 항목은 번역·구절 ID(책·장·절)·표시 시각·개인 묵상·묵상 수정 시각이다. 원문 HTML·성경 원문 문자열·도움 전문은 저장 항목에 복제하지 않는다. 읽기 설정은 글자 크기·줄 간격·테마만 별도로 저장한다.

읽기와 마이페이지는 동일한 저장소를 사용한다. 프로젝트 전용 이름공간과 스키마 버전을 사용해 다른 GitHub 프로젝트 사이트와 충돌하지 않게 한다. 묵상 필드가 없는 기존 표시 데이터는 미작성으로 읽으며 구절을 보존한다. 다른 탭의 저장 변경을 반영하되 편집 중 초안을 조용히 덮어쓰지 않는다.

데이터는 같은 기기·브라우저 프로필·사이트의 localStorage에 남는다. 계정·기기 간 자동 동기화와 백업은 없다. 브라우저 데이터 삭제·비공개 탐색 종료·사이트 출처 변경으로 접근할 수 없게 될 수 있다. 묵상을 GitHub 저장소·서버·배포 파일·분석 로그에 전송하지 않는다.

화면 안내: ‘구절과 묵상은 이 기기와 브라우저에 저장됩니다. 브라우저 데이터를 지우면 함께 삭제됩니다.’

저장·해제·되돌리기 성공을 확인한 뒤 UI를 갱신한다. 실패는 성공으로 알리지 않는다. 불러오기 오류는 정상 빈 목록과 구별하며 기존 값을 빈 데이터로 덮어쓰거나 자동 삭제하지 않는다. 저장 실패 시 입력 초안을 지우지 않는다.

## 9. 본문 권리와 이미지

개역개정 전체 장을 서비스 안에서 연속 제공하는 것이 최종 요구다. 다만 웹 표시·공개 저장소 포함·배포 조건이 확인된 본문만 포함한다. 공식 API가 있다고 가정하지 않는다. 권리 조건이 확정되기 전에는 검증된 짧은 발췌와 장절·서비스 작성 설명·공식 본문 링크로 현재 제공 범위를 정확히 알린다. 전체 장이 내장된 것처럼 표시하지 않는다.

Figma와 초기 공개 콘텐츠는 기존에 확인한 데살로니가전서 5:16–20 발췌를 재사용한다. 이 문서에 원문을 추가 인용하지 않는다. 본문 확인은 [대한성서공회 개역개정 5장](https://www.bskorea.or.kr/bible/korbibReadpage.php?book=1th&chap=5&version=GAE)과 [1장](https://www.bskorea.or.kr/bible/korbibReadpage.php?book=1th&chap=1&version=GAE)을 기준으로 한다.

이미지가 필요한 대목에만 Google로 후보를 찾고 원본 제공처에서 PD·CC0 조건을 확인한다. 검색 결과 사용 권한만으로 채택하지 않는다. 이미지의 작가·원출처·라이선스·자료 성격을 알리고 실제 성경 장소·인물·복식의 증거로 임의 연결하지 않는다. 현재 서신 설명에는 불필요한 풍경 이미지를 붙이지 않는다.

## 10. 접근성과 상태

본문·출처·보조 문구의 충분한 명암을 유지한다. 저장 효과는 밑줄·배경색·버튼 상태를 함께 사용한다. 주요 조작은 44×44px 이상을 목표로 하고 키보드로 모든 핵심 흐름을 사용할 수 있게 한다.

묵상 입력에는 장절과 연결된 레이블, 글자 수, 오류 설명을 연결한다. 저장 결과는 화면 읽기 프로그램에도 알린다. 확인 대화상자는 초점을 가두고 취소 시 호출 버튼으로 되돌린다. 정적인 Figma의 초점 동작은 개발 후 실제 브라우저에서 검증한다.

필수 예외는 미선택·설명 미등록·외부 본문·잘못된 URL·빈 목록·필터 결과 없음·이미지/근거 오류·저장/불러오기 오류·묵상 저장 실패·미저장 초안·묵상 동시 삭제 확인이다. 실패를 빈 화면이나 저장 성공으로 위장하지 않는다.

## 11. 개발과 게시

대상 저장소는 [ejee2/biblejeong](https://github.com/ejee2/biblejeong)다. GitHub Pages에서 /biblejeong/ 하위 경로가 작동하는 정적 사이트로 게시한다. 읽기 index.html과 mypage/index.html을 각각 제공해 직접 주소 접근과 새로고침을 지원한다. 서버·회원 DB·CMS를 추가하지 않는다.

화면 담당은 반응형 읽기·마이페이지·묵상 UI를, 저장 연결 담당은 구절·묵상 상태와 오류·복원을, 배포 담당은 Pages 경로·자동 게시·실제 응답 검증을 맡는다. 기획·디자인은 이 문서와 Figma에서 작성·저장 후·실패 상태를 맞춘다.

Git에는 코드·검수한 공통 콘텐츠·문서·설정만 포함한다. 개인 묵상은 포함하지 않는다. 잘못된 콘텐츠를 게시 대상에서 제외하고 Git 기록으로 이전 버전 복구가 가능해야 한다. 원격 커밋과 실제 Pages 응답을 확인하기 전에는 게시 완료라고 보고하지 않는다.
